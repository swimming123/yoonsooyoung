`.env` 파일 때문에 두 번 헤맸다. 둘 다 "서버가 이상하다"고 생각했는데 원인은 프론트의 환경 변수였다.

## 1. 나는 되는데 너는 안 된다

### 증상

1. Vue 화면은 열린다.
2. 그런데 Django와 데이터를 주고받지 못한다.
3. CORS 문제인가 싶었지만, CORS는 이미 열어 둔 상태였다.

### 원인

프론트 `.env`의 백엔드 주소가 이렇게 돼 있었다.

```
VITE_BACKEND_URL=http://localhost:8000/api
```

`localhost`는 **브라우저가 돌고 있는 그 컴퓨터**를 뜻한다. 내 PC에서 백엔드를 띄우고 내 브라우저로 볼 때는 맞지만, 다른 사람이 개발 서버 주소로 접속하면 그 사람 컴퓨터의 8000번 포트로 요청이 간다. 거기엔 백엔드가 없다.

### 해결

백엔드가 실제로 떠 있는 서버 주소로 바꿨다.

```
VITE_BACKEND_URL=http://<개발 서버 주소>:<포트>/api
```

## 2. 프록시를 바꿨는데 여전히 다른 포트로 나간다

### 증상

HTTPS 인증서 문제를 피하려고 Vite 프록시의 target을 백엔드로 바꿨다. 그런데 브라우저 네트워크 탭을 보면 요청이 여전히 예전 포트로 바로 나가고, 됐다 안 됐다 했다.

### 원인

```js
await axios.post(`${import.meta.env.VITE_BACKEND_URL}/join/register/`, { ... })
```

`VITE_BACKEND_URL`에 `https://서버:예전포트/api` 같은 **전체 주소**가 들어 있으니, 브라우저가 프록시를 거치지 않고 그 주소로 직접 요청한다. 프록시는 **개발 서버 자기 자신**(`/api/...` 같은 상대 경로)으로 온 요청만 넘겨준다.

직접 요청하니 자체 서명 인증서를 브라우저가 믿지 않거나, 그 포트의 서버가 꺼져 있으면 실패했다.

### 해결

```
# .env
VITE_BACKEND_URL=/api
```

```js
// vite.config.js
server: {
  proxy: {
    '/api': { target: 'https://<백엔드 주소>:8000', changeOrigin: true, secure: false },
  },
},
```

이제 요청 흐름은 `브라우저 → /api/join/register/ → Vite 프록시 → 백엔드`가 된다. `secure: false`는 개발용 자체 서명 인증서를 프록시가 받아들이게 하는 옵션이다(운영에서는 쓰지 않는다).

## .env를 바꿨는데 반영이 안 될 때

- Vite는 `.env`를 **개발 서버를 시작할 때** 읽는다. 바꿨으면 `npm run dev`를 다시 실행한다.
- `.env.local`, `.env.development`처럼 여러 파일이 있으면 우선순위가 있다. 같은 키가 다른 파일에 있으면 생각과 다른 값이 쓰인다.
- 지금 어떤 값이 들어갔는지 화면에서 확인해 보면 빠르다: `console.log(import.meta.env.VITE_BACKEND_URL)`

## 정리

- `localhost`는 "브라우저가 있는 컴퓨터"다.
- 프록시를 쓰려면 요청 주소를 상대 경로(`/api`)로 둔다.
- `.env`를 바꾸면 개발 서버를 재시작한다.
- `VITE_`로 시작하는 값은 빌드 결과물에 그대로 들어가니 비밀 값은 넣지 않는다.
