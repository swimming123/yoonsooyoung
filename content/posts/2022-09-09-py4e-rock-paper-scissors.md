## 조건문

### if 문

```python
x = 5

if x < 10:
    print('smaller')
```

`if`는 예약어다. `if` 다음에 오는 조건이 True인지 False인지 판단해서, True면 아래 코드를 실행한다. False면 `elif`나 `else`가 있을 때 그쪽이 실행되고, 아무것도 없으면 아무것도 실행되지 않는다.

파이썬은 들여쓰기를 엄격하게 따진다. 들여쓰기로 어떤 문장이 어디에 속하는지 판단하기 때문이다.

```python
x = 5

if x < 10:
print('smaller')
```

이렇게 쓰면 들여쓰기 오류(`IndentationError`)가 난다. 들여쓰기 한 번은 Tab 1번 또는 Space 4번으로 한다.

### if-else 문

```python
x = 11

if x < 10:
    print('smaller')
else:
    print('Bigger')
```

`if` 조건이 True면 바로 아래 문장을, False면 `else:` 아래 문장을 실행한다. 그래서 이 코드는 `Bigger`를 출력한다.

> **if-else를 쓸 때 주의할 점**
>
> 1. 조건 뒤에 `:`(콜론)을 찍어야 한다.
> 2. 조건이 참일 때 실행할 코드는 들여쓰기를 해야 한다.

## 가위바위보 미션

가위바위보 미션이 2주 동안 나왔다.

첫 주에는 난수를 생성해서 컴퓨터와 가위바위보를 하는 코드를 짜는 게 미션이었다. 가위·바위·보 또는 0·1·2로 규칙을 정하고 컴퓨터와 내 값을 비교하면 돼서 금방 풀었다.

```python
# 사용자가 이기는 경우, 비기는 경우, 컴퓨터가 이기는 경우로 나눔
if (my == '가위' and com == 3) or (my == '바위' and com == 1) or (my == '보' and com == 2):
    ...
elif (my == '가위' and com == 1) or (my == '바위' and com == 2) or (my == '보' and com == 3):
    print("비겼습니다!")
...
```

다음 주에는 조건이 몇 개 추가됐다. 가위·바위·보나 0·1·2가 아닌 값이 들어오면 다시 입력받고, 게임이 끝나면 총 전적을 출력해야 했다. 나는 한 판이 끝날 때마다 전적을 출력해서, 조건과는 다른 결과가 나왔다.

3주차부터는 팀원이 생겨서 같이 문제를 풀었다. 다른 팀원들은 게임 전적을 가위바위보 `if` 문 밖에서 출력했다. 나는 이기거나 비기거나 질 때마다 출력문을 넣었는데, 승수를 저장할 변수를 다루는 게 서툴렀던 것 같다.

```python
if (my == '가위' and com == 3) or (my == '바위' and com == 1) or (my == '보' and com == 2):
    win_user = win_user + 1
    print("사용자 승리!")
    print("--------------------------------------")
    print('사용자 {}승 {}패'.format(win_user, win_com))
    print('컴퓨터 {}승 {}패'.format(win_com, win_user))
```

지금 전체 코드를 다시 보니, 굳이 전적 출력을 저기에 넣었어야 했나, 한 번에 밖에서 처리할 수는 없었나 하는 생각이 든다.

### 두 가지 구현 방법

**첫 번째 방법**은 내 입력값을 기준으로 컴퓨터 값을 비교하는 방식이었다.

- 게임 수 = 1, 유저 승 = 0, 컴퓨터 승 = 0으로 선언
- 유저 입력
- 컴퓨터 랜덤 출력
- 가위바위보 비교 `if` 문
    - 유저가 가위일 때
        - 컴퓨터가 가위일 때
        - 컴퓨터가 바위일 때: 컴퓨터 승 += 1
        - 컴퓨터가 보일 때: 유저 승 += 1

**두 번째 방법**은 역할마다 함수를 나누는 방식이었다.

- 유저 입력 함수, 컴퓨터 출력 함수를 만든다.
- 두 값을 비교해서 승패를 계산하는 함수를 만든다.
- 게임을 반복하는 함수를 만들어서, 게임 반복과 전적 출력을 맡긴다.

### 느낀 점

여러 사람의 코드를 보면서, 같은 조건을 보고도 각자 다르게 구현하는 게 신기했다. 그리고 내가 짠 코드는 재사용하기 어려운 코드였다. 유저, 컴퓨터, 비교, 게임 반복 함수를 따로 만들면 나중에 조건을 추가하기도 편하고, 다른 사람이 알아보기도 쉬워 보였다.

3주차에 다짐한 것은 이렇다.

- 주석 작성을 습관으로 만들기
- 변수 이름은 최대한 알아보기 쉽게 (줄임말을 쓴다면 주석에 원래 이름 적기)
- 조건을 함수로 만들고, 중복되는 코드는 최대한 없애기

4주차에는 이런 미션을 구현했다.

- 내장 함수를 쓰지 않고, 같은 역할을 하는 사용자 정의 함수 만들기
- 임의의 글에서 글자 수를 세고 결과를 txt 파일로 저장하기
- 테이블에서 행 정보를 입력받고 규칙에 어긋난 리스트 만들기
