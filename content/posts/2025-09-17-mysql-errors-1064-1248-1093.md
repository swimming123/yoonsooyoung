## 1064: You have an error in your SQL syntax

### 오류 메시지

```
pymysql.err.ProgrammingError: (1064, "You have an error in your SQL syntax; check the manual
that corresponds to your MySQL server version for the right syntax to use near
'delete'>'  and a.is_deleted = 'N'  and a.is_open = 'Y'' at line 1")
```

### 원인

LDAP 계정 삭제 API의 뷰 함수가 이렇게 생겼었다.

```python
def ldap_delete(user_id):
    item = UsersModel().select_user_one({'id': user_id, 'is_deleted': 'N', 'is_open': 'Y'})
```

그런데 Django는 뷰 함수의 **첫 번째 인자로 항상 `request` 객체**를 넘긴다. 그래서 `user_id` 자리에 request가 들어갔다.

조회 함수는 값을 문자열로 이어 붙이고 있었다.

```python
query += " and a.id = '" + str(where.get('id')) + "' "
```

`str(request)`는 `<WSGIRequest: POST '/api/users/ldap-delete'>` 같은 문자열이다. 여기에 들어 있는 작은따옴표 `'`가 SQL의 따옴표를 닫아 버리면서 `...ldap-delete'>'` 부분에서 문법 에러가 났다. 에러 메시지의 `near 'delete'>'`가 바로 그 흔적이다.

### 해결

뷰 함수는 `request`를 첫 번째 인자로 받고, 필요한 값은 URL이나 요청 본문에서 꺼낸다.

```python
# URL: path('api/users/<int:user_id>/ldap-delete', views.ldap_delete)
def ldap_delete(request, user_id):
    ...

# 또는 본문에서
def ldap_delete(request):
    user_id = json.loads(request.body).get('user_id')
```

그리고 이번 일은 **문자열로 SQL을 이어 붙이면 따옴표 하나로 쿼리가 깨진다**는 걸 그대로 보여 준다. 공격자가 일부러 넣으면 SQL 인젝션이다. 값은 `cursor.execute(query, params)`처럼 파라미터로 넘기자.

## 1248: Every derived table must have its own alias

### 오류 메시지

```
Error Code: 1248. Every derived table must have its own alias
```

### 원인과 해결

MySQL은 `FROM` 절의 서브쿼리(파생 테이블)에 반드시 별칭을 붙여야 한다.

```sql
-- ❌
SELECT id FROM (SELECT id FROM projects WHERE status = 'START');

-- ✅
SELECT id FROM (SELECT id FROM projects WHERE status = 'START') AS t;
```

## 1093: You can't specify target table for update in FROM clause

### 오류 메시지

```
Error Code: 1093. You can't specify target table 'p' for update in FROM clause
```

### 원인

특정 조건의 프로젝트들을 한 번에 `STOP`으로 바꾸려고 했다. 조건이 복잡해서 먼저 SELECT로 대상을 확인하고, 그 SELECT를 그대로 `IN (...)` 안에 넣었다.

```sql
UPDATE projects SET status = 'STOP'
WHERE id IN (
  SELECT p.id
  FROM projects p
  JOIN collection_presets cp ON p.preset_id = cp.preset_id
  WHERE p.status = 'START' AND p.owner_id = 55 AND cp.collection_id = (...)
);
```

MySQL은 **수정하는 테이블을 같은 문장의 서브쿼리에서 다시 읽을 수 없다.** (Oracle이나 PostgreSQL은 된다.)

### 해결

서브쿼리를 한 번 더 감싸서 파생 테이블(임시 결과)로 만들면 MySQL이 먼저 결과를 만들어 둔 뒤 UPDATE를 한다. 이때 위의 1248 때문에 별칭도 꼭 붙인다.

```sql
UPDATE projects SET status = 'STOP'
WHERE id IN (
  SELECT id FROM (
    SELECT p.id
    FROM projects p
    JOIN collection_presets cp ON p.preset_id = cp.preset_id
    WHERE p.status = 'START' AND p.owner_id = 55 AND cp.collection_id = (...)
  ) AS target
);
```

JOIN을 쓴 UPDATE로 바꾸는 방법도 있다.

```sql
UPDATE projects p
JOIN collection_presets cp ON p.preset_id = cp.preset_id
SET p.status = 'STOP'
WHERE p.status = 'START' AND p.owner_id = 55 AND cp.collection_id = (...);
```

여러 행을 한꺼번에 바꾸는 쿼리는 실행 전에 SELECT로 대상과 개수를 꼭 먼저 확인하자.
