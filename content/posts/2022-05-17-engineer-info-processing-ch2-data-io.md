2장 데이터 입출력 구현은 "용어를 설명하시오", "설명을 보고 용어를 쓰시오", "영문 키워드 보기에서 고르시오" 형태로 나왔다. 영문으로 된 키워드는 한 번씩 다 나왔던 것 같다.

SQL 파트와 같이 공부하면 좋다. `SELECT` 문만 주구장창 외우다가 개념이랑 같이 보니까 이해가 되는 것 같기도 하고...

## 자주 쓰는 SQL 문 형태

```sql
CREATE TABLE ~ PRIMARY KEY ~ NOT NULL ~ FOREIGN KEY ~ REFERENCES ~ ON DELETE / ON UPDATE ~ CONSTRAINT ~
CREATE INDEX ~ ON ~
ALTER TABLE ~ ADD / ALTER / DROP
DROP ~ CASCADE / RESTRICT

GRANT ~ TO,  REVOKE ~ FROM,  ROLLBACK,  SAVEPOINT

INSERT INTO ~ VALUES
DELETE FROM ~ WHERE ~
UPDATE ~ SET ~ WHERE ~
SELECT ~ FROM ~ WHERE ~ GROUP BY ~ HAVING ~ ORDER BY ASC / DESC

table1 LEFT / RIGHT OUTER JOIN table2 ON table1.A = table2.A
table1 NATURAL JOIN table2

SUM()  AVG()  COUNT()  LIKE '윤%'  LIKE '윤_'
```

## 데이터 저장소와 데이터베이스

- **데이터 저장소**: 데이터를 논리적인 구조로 조직하거나 물리적인 공간에 구축한 것
- **데이터베이스(Database)**: 여러 사람이 공동으로 쓸 데이터를 중복 없이 통합해 저장하고, 언제든 쓸 수 있게 운영하는 데이터
    - 통합된 데이터(Integrated Data): 자료의 중복을 배제
    - 저장된 데이터(Stored Data): 컴퓨터가 접근할 수 있는 저장 매체에 저장
    - 운영 데이터(Operational Data): 조직의 고유 업무에 꼭 필요한 자료
    - 공용 데이터(Shared Data): 여러 응용 시스템이 공동으로 소유
- **DBMS(Database Management System)**: 사용자 요구에 따라 정보를 만들어 주고 데이터베이스를 관리하는 소프트웨어(미들웨어). 기능은 정의(Definition), 조작(Manipulation), 제어(Control)
- **데이터 독립성**
    - 논리적 독립성: 응용 프로그램과 DB를 독립시켜, 논리 구조를 바꿔도 프로그램에 영향이 없음
    - 물리적 독립성: 응용 프로그램과 보조 기억 장치를 독립시켜, 디스크를 추가·변경해도 프로그램에 영향이 없음

## 스키마(Schema)

데이터베이스의 구조와 제약 조건에 관한 전반적인 명세.

- 외부 스키마: 사용자 입장에서 필요한 데이터베이스의 논리적 구조
- 개념 스키마: 데이터베이스 전체의 논리적 구조. 하나만 존재
- 내부 스키마: 물리적 저장 장치 입장. 레코드 형식, 항목 표현 방법 등

## 데이터베이스 설계

고려 사항: 무결성, 일관성, 회복, 보안, 효율성, 확장성

**설계 순서**: 요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현

- 개념적 설계(정보 모델링, 개념화): 현실 세계를 추상적 개념으로 표현. E-R 다이어그램
- 논리적 설계(데이터 모델링): 특정 DBMS가 지원하는 논리적 자료 구조로 변환. 트랜잭션 인터페이스 설계
- 물리적 설계(데이터 구조화): 논리적 구조의 데이터를 물리적 구조로 변환

## 데이터 모델

현실 세계의 정보를 단순화·추상화해 체계적으로 표현한 개념적 모형.

- 구성 요소: 개체(Entity), 속성(Attribute), 관계(Relationship)
- 종류: 개념적, 논리적, 물리적 데이터 모델
- 표시할 요소: 구조(Structure), 연산(Operation), 제약 조건(Constraint)
- **개념적 데이터 모델**: 사람이 현실 세계를 이해하기 쉽게 추상적 개념으로 표현. E-R 모델
- **논리적 데이터 모델**: 개념적 구조를 컴퓨터 환경에 맞게 변환한 것

**구성 요소 자세히**

- **개체(Entity)**: DB에 표현하려는 현실 세계의 대상(개념, 정보 등)
- **속성(Attribute)**: 데이터베이스를 구성하는 가장 작은 논리적 단위. 속성 개수는 디그리(Degree, 차수)
    - 기본키 속성(개체를 유일하게 식별), 외래키 속성(다른 개체와의 관계), 일반 속성(그 외)
- **관계(Relationship)**: 개체와 개체 사이의 논리적 연결
    - 일대일, 일대다, 다대다
    - 종속 관계(Dependent), 중복 관계(Redundant), 재귀 관계(Recursive), 배타 관계(Exclusive)

**E-R 모델(개체-관계 모델)**: 피터 첸이 제안한 개념적 데이터 모델

- 사각형: 개체
- 마름모: 관계
- 타원: 속성 (이중 타원은 다중값 속성, 밑줄 타원은 기본키 속성, 타원에 타원이 달린 것은 복합 속성)

## 관계형 데이터베이스

2차원 표를 이용해 데이터 사이의 관계를 정의하는 데이터베이스.

- **튜플(Tuple)**: 행. 튜플 개수는 카디널리티(Cardinality, 기수, 대응수)
- **속성(Attribute)**: 가장 작은 논리적 단위. 속성 개수는 디그리(Degree, 차수)
- **도메인(Domain)**: 하나의 속성이 가질 수 있는 같은 타입의 원자값 집합

**릴레이션의 특징**

- 한 릴레이션 안의 튜플은 모두 다르다.
- 튜플 사이에 순서가 없고, 속성의 순서도 중요하지 않다.
- 속성 이름은 유일하지만, 속성 값은 중복될 수 있다.
- 속성 값은 원자값이다.

**관계형 데이터 모델**: 기본키(Primary Key)와 이를 참조하는 외래키(Foreign Key)로 관계를 표현한다. 대표 언어는 SQL.

## 키(Key)

조건에 맞는 튜플을 찾거나 정렬할 때 기준이 되는 속성.

| 키 | 설명 |
| --- | --- |
| 후보키(Candidate Key) | 튜플을 유일하게 식별할 수 있는 속성들의 부분집합. 유일성과 최소성을 모두 만족 |
| 기본키(Primary Key) | 후보키 중에서 고른 메인 키. 중복 없음, NULL 불가 |
| 대체키(Alternate Key) | 후보키가 둘 이상일 때 기본키를 뺀 나머지 후보키. 보조키 |
| 슈퍼키(Super Key) | 속성들의 집합으로 구성된 키. 유일성은 만족, 최소성은 만족하지 않음 |
| 외래키(Foreign Key) | 다른 릴레이션의 기본키를 참조하는 속성 또는 속성들의 집합 |

## 무결성(Integrity)

데이터베이스에 저장된 값과 현실 세계의 실제 값이 일치하는 정확성.

- 개체 무결성: 기본키 속성은 NULL이나 중복값을 가질 수 없다.
- 참조 무결성: 외래키는 NULL이거나 참조하는 릴레이션의 기본키 값과 같아야 한다(참조할 수 없는 외래키는 안 됨).
- 도메인 무결성: 속성 값은 정의된 도메인에 속해야 한다.
- 무결성 강화 방법: 애플리케이션, 데이터베이스 트리거, 제약 조건

## 관계 대수와 관계 해석

**관계 대수**: 원하는 정보를 어떻게 유도할지 기술하는 절차적 언어.

| 연산 | 기호 | 설명 |
| --- | --- | --- |
| Select | σ (시그마) | 조건을 만족하는 튜플의 부분집합. 수평 연산 |
| Project | π (파이) | 지정한 속성 값만 추출, 중복 제거. 수직 연산 |
| Join | ⋈ | 공통 속성을 중심으로 두 릴레이션을 합침. 교차곱 후 Select |
| Division | ÷ | A에서 B의 속성을 모두 가진 튜플을 골라, B 속성을 뺀 나머지 |
| 합집합 Union | ∪ | |
| 교집합 Intersection | ∩ | |
| 차집합 Difference | − | |
| 교차곱 Cartesian Product | × | |

**관계 해석**: 관계 데이터 연산을 표현하는 방법. 비절차적이며 수학(술어 해석)에 기반한다.

## 이상(Anomaly)과 정규화

**이상**: 데이터 중복 때문에 생기는 문제.

- 삽입 이상(Insertion): 데이터를 넣을 때 원하지 않는 값까지 필요해서 넣을 수 없게 되는 현상
- 삭제 이상(Deletion): 한 튜플을 지울 때 상관없는 값까지 함께 지워지는 현상(연쇄 삭제)
- 갱신 이상(Update): 속성 값을 바꿀 때 일부만 바뀌어 정보가 서로 맞지 않게 되는 현상

**함수적 종속(Functional Dependency)**: 속성 X의 값 하나에 Y의 값이 항상 하나만 대응할 때, Y는 X에 함수적으로 종속된다(X → Y).

**정규화(Normalization)**: 테이블을 무손실 분해하는 과정.

| 정규형 | 조건 |
| --- | --- |
| 제1정규형 | 모든 도메인이 원자값 (한 칸에 값이 여러 개거나 반복되는 정보는 분리) |
| 제2정규형 | 부분 함수적 종속 제거 (기본키가 아닌 속성이 기본키 전체에 완전 함수적 종속) |
| 제3정규형 | 이행 함수적 종속 제거 |
| BCNF | 모든 결정자가 후보키 |
| 제4정규형 | 다중 값 종속 제거 |
| 제5정규형 | 조인 종속 제거 |

**반정규화(Denormalization)**: 성능을 위해 의도적으로 정규화를 어기고 통합·중복·분리하는 것. 테이블 통합, 테이블 분할, 중복 테이블 추가, 중복 속성 추가.

## 시스템 카탈로그

- **시스템 카탈로그(System Catalog)**: 다양한 객체에 관한 정보를 담은 시스템 데이터베이스
- **메타데이터(Metadata)**: 시스템 카탈로그에 저장된 정보
- **데이터 디렉터리(Data Directory)**: 데이터 사전에 수록된 데이터에 접근하는 데 필요한 정보를 관리·유지하는 시스템

## 트랜잭션(Transaction)

논리적 기능을 수행하기 위한 작업 단위. 한꺼번에 모두 수행되어야 하는 연산들.

- 원자성(Atomicity): 모두 반영(커밋)되거나 하나도 반영되지 않아야(롤백) 한다.
- 일관성(Consistency): 실행을 마치면 일관성 있는 상태여야 한다.
- 독립성(Isolation): 실행 중에 다른 연산이 끼어들 수 없다.
- 영속성(Durability): 완료된 결과는 시스템이 고장 나도 영구히 반영되어야 한다.

**CRUD 분석**: Create, Read, Update, Delete 관점에서 프로세스와 데이터의 관계를 분석.

## 인덱스, 뷰, 클러스터, 파티션

**인덱스(Index)**: 레코드에 빠르게 접근하려고 <키, 포인터> 쌍으로 구성한 데이터 구조.

- 종류: 트리 기반, 비트맵, 함수 기반, 비트맵 조인, 도메인
- 클러스터드 인덱스: 키 순서대로 데이터가 정렬되어 있어 데이터를 빠르게 찾을 수 있다.
- 넌클러스터드 인덱스: 키 값만 정렬되어 있고 실제 데이터는 정렬되어 있지 않다.

**뷰(View)**: 하나 이상의 기본 테이블에서 유도한 가상 테이블. `CREATE`, `DROP`으로 만들고 지운다.

- 장점: 논리적 독립성, 데이터 관리가 간단
- 단점: 독립적인 인덱스를 가질 수 없음, 정의를 변경할 수 없음, 삽입·삭제·갱신에 제약

**클러스터(Cluster)**: 같은 성격의 데이터를 같은 데이터 블록에 저장. 조회는 빠르지만 입력·수정·삭제 성능은 떨어진다.

**파티션(Partition)**: 대용량 테이블이나 인덱스를 작은 논리적 단위인 파티션으로 나누는 것.

- 장점: 쿼리 성능 향상, 디스크 성능 향상, 손상 범위 최소화, 파티션 단위로 입출력 분산
- 단점: 세심한 관리 필요, 조인 비용 증가, 작은 테이블에 쓰면 오히려 성능 저하
- 종류: 범위 분할, 해시 분할, 조합 분할
