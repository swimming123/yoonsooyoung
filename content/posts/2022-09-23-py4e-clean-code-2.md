## 함수화

정보통신공학과를 졸업해서 프로그래밍 언어가 낯설지는 않지만, 학점만 '적당히' 받으려고 공부해서 **지금은 아무것도 기억이 안 난다.**

"입력받은 값을 이렇게 저렇게 해서 이렇게 출력하세요" 같은 간단한 조건이 있으면, 그 조건대로 돌아가는 코드는 만들 수 있다. 만들긴 하는데 가독성도 떨어지고 재사용하기도 어려운, 일회용 코드만 만들고 있었다.

2주차 미션에 연봉 구간에 따라 세금을 계산해서 "세후 연봉은 OO만 원입니다"처럼 출력하는 문제가 있었다. 나는 정말 무식하게 `if-elif-else` 조건 하나하나에 `print`를 썼다.

```python
# 연봉 구간에 따라 세율 계산 (연봉 - 연봉 * 세율)
if yearly_payment <= 1200:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.06)))
elif yearly_payment <= 4600:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.15)))
elif yearly_payment <= 8800:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.24)))
elif yearly_payment <= 15000:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.35)))
elif yearly_payment <= 30000:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.38)))
elif yearly_payment <= 50000:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.40)))
else:
    print('세후 연봉 : {} 만원'.format(yearly_payment - (yearly_payment * 0.42)))
```

제출하면서도 이건 좀 고쳐야 할 것 같다는 생각은 했지만, 급한 일이 있어서 시간을 많이 쓸 수 없었다 ㅜ

미션 피드백에서 코딩 코치님이 정확히 짚어 주셨다. 조건문 안에서 반복되는 코드는 계산에 쓰는 숫자만 변수에 담고, **출력문은 조건문 밖에** 쓰는 게 가독성 좋은 코드라고 했다.

여기서 반복되는 코드는 `print('세후 연봉 : {} 만원'.format(...))`에서 곱하는 숫자를 뺀 나머지 전부다. 그래서 이렇게 바꿔 봤다.

```python
rate = -1
if yearly_payment <= 1200:
    rate = 0.94
elif 1200 < yearly_payment <= 4600:
    rate = 0.85
elif 4600 < yearly_payment <= 8800:
    rate = 0.76
elif 8800 < yearly_payment <= 15000:
    rate = 0.65
elif 15000 < yearly_payment <= 30000:
    rate = 0.62
elif 30000 < yearly_payment <= 50000:
    rate = 0.60
elif yearly_payment > 50000:
    rate = 0.58

print('세전 연봉 : ', yearly_payment, '만원')
print('세후 연봉 : ', int(yearly_payment * rate), '만원')
```

`if` 문에서는 `rate` 값만 정하고, 조건문 밖의 출력문에서 그 값을 쓰는 코드가 됐다. 처음 코드와 비교하면 확실히 간결하고 읽기 쉽다.

## 예외 처리

오류(error)가 생기면 결함(defect)이 생기고, 결함은 장애(failure)로 이어진다. 예상치 못한 오류로 결함이 생기면 프로그램이 제대로 동작할 수 없다. 이런 상황에 대비해서 예외 처리를 한다.

파이썬의 예외 처리에는 `try-except`, `try-finally`가 있다.

### try-except

기본 구조는 이렇다.

```python
try:
    실행할 코드
except [발생 오류 [as 오류 메시지 변수]]:
    오류가 나면 실행할 코드
```

`except`에 오류 종류를 지정해서 오류 메시지를 알려 줄 수도 있고, 종류를 지정하지 않고 모든 예외에 적용되는 코드만 쓸 수도 있다.

```python
def make_comma(n):
    print("{:,}".format(n))

while True:
    try:
        number = int(input('숫자를 입력해 주세요'))
        make_comma(number)
        break
    except:
        print("숫자만 입력해 주세요")
```

`int`로 바꿀 수 없는 값이 들어오면 `except:`가 "숫자만 입력해 주세요"를 출력한다.

원래는 내장 함수 대신 같은 일을 하는 사용자 정의 함수를 만드는 문제였는데, 문제를 잘못 이해해서 `format` 함수를 썼다 ㅋㅋㅋ 어쩐지 빨리 끝난다 했다.

### try-finally

`finally` 절은 예외 발생 여부와 상관없이 항상 실행된다. 그래서 사용한 리소스를 닫아야 할 때 쓴다.

```python
f = open('foo.txt', 'w')
try:
    # 무언가를 수행한다.
    ...
finally:
    f.close()

# 코드 참조: 점프 투 파이썬 위키독스
```

`open()`으로 `foo.txt` 파일을 쓰기 모드(`w`)로 열고, `finally`에서 `close()`로 파일을 닫는다.

### 여러 오류 처리하기

여러 종류의 오류를 처리하려면 `except`를 2개 이상 쓴다.

```python
try:
    ...
except 발생오류1:
    ...
except 발생오류2:
    ...

# 예시
try:
    a = [1, 2]
    print(a[3])
    4 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")
except IndexError:
    print("인덱싱할 수 없습니다.")

# 코드 참조: 점프 투 파이썬 위키독스
```

### try-except-else

`try`에서 오류가 나지 않았을 때만 실행할 코드가 있다면 `else` 절을 쓴다.

```python
try:
    age = int(input('나이를 입력하세요: '))  # 숫자만 입력 가능
except:
    print('입력이 정확하지 않습니다.')  # 숫자가 아닌 값이 들어오면 except 실행
else:
    # 숫자를 제대로 입력받아 try가 정상 동작하면 else 실행
    if age <= 18:
        print('미성년자는 출입금지입니다.')
    else:
        print('환영합니다.')

# 코드 참조: 점프 투 파이썬 위키독스
```

## 마치며

이번 글에서는 깔끔하게 코드 작성하는 방법 2, 함수화와 예외 처리를 정리해 봤습니다.

같은 문제를 풀어도 어떤 사람의 코드는 구조가 한눈에 보여서 이해하기 쉽고, 어떤 코드는 로직은 내 것보다 좋아 보이는데 분석하기 어렵거나 가져다 쓰기 어려웠습니다. 이럴 때 주석으로 설명을 달거나 기능별로 함수를 나눠 구조를 단순하게 만들면, 다른 사람이 봐도 이해하기 쉬울 것 같습니다.

그리고 잘 돌아가는 코드라도 정상 범위를 벗어나는 값을 넣어 테스트해 보면, 예외 처리가 필요한 부분이나 로직이 엉킨 부분을 찾을 수 있습니다. 참고로 소프트웨어 테스트 이론 중 블랙박스 테스트에 동등 분할 테스트와 경계값 분석 테스트가 있습니다.

- **동등 분할 테스트**: 입력값을 일정 범위로 나누고, 각 범위의 중간값을 넣어 보는 테스트
- **경계값 분석 테스트**: 오류는 중간값보다 경계값에서 더 많이 난다는 점에 착안해, 데이터 범위의 경계값을 넣어 보는 테스트

예를 들어 학점을 계산하는 프로그램이 있고, 조건이 이렇다고 해 봅시다.

| 학점 | 범위 |
| --- | --- |
| A | 4.0 ~ 4.5 |
| B | 3.5 ~ 3.9 |
| C | 3.0 ~ 3.4 |
| D | 2.5 ~ 2.9 |
| F | 0 ~ 2.4 |

동등 분할 테스트를 한다면 4.3, 3.2, 1.0을 넣었을 때 A, C, F가 나와야 합니다. 여기서 오류가 난다면 입력 부분이나 학점 조건문에 문제가 있다고 짐작할 수 있습니다.

경계값 분석 테스트라면 4.6, 3.5, 2.5, 0, -1을 넣어 볼 수 있습니다. 예상과 다른 값이 나온다면, 위의 오류에 더해 4.5를 넘는 값과 0 미만의 값에 대한 예외 처리가 빠졌구나 생각할 수 있습니다.
