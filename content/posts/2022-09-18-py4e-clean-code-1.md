6주 동안 코딩 코치님이 가장 많이 언급한 걸 고르자면 "변수 이름", "주석", "들여쓰기", "함수화"라고 생각한다. 4주차 무렵까지 변수 이름과 주석에 대한 피드백이 계속 있었고, 나도 미션 코드가 복잡해질수록 변수 이름을 어떻게 지을지 고민이 생겼다.

그래서 이번에는 변수 이름, 주석, 들여쓰기를 정리해 보려고 한다.

## 변수 이름

> **변수**: 데이터를 저장하기 위해 프로그램이 이름을 붙여 둔 메모리 공간
>
> **변수 이름**: 변수가 저장될 메모리 공간을 부르는 이름

'급여'를 담는 변수를 만든다고 해 보자.

```python
# 급여 변수 선언
p = 0
```

이렇게 무엇인지 유추할 수 없는 이름은 피하라고 했다. 코딩 코치님은 누가 봐도 어떤 변수인지 알 수 있게 이름을 짓는 게 협업의 기본이라고 했다. 예를 들면 단어를 그대로 변수 이름으로 쓰는 방법이 있다.

```python
# 급여 변수 선언
# 길더라도 의미를 알 수 있게
payment = 0
```

학교 과제나 개인 프로젝트를 할 때는 변수 이름에 크게 신경 쓰지 않았던 것 같다. `a = 10`, `char i = 'a'`처럼 아무 생각 없이 만들었는데, 다른 사람의 코드를 참고하게 되면서 변수 이름이 얼마나 중요한지 느꼈다.

우리 팀이 변수 이름으로 피드백을 받은 부분은 이랬다.

```python
import random

def player():
    my_sel = 0
```

가위바위보 코드의 일부로, `player()` 함수 안에 사용자가 고른 가위·바위·보를 저장할 변수를 선언한 부분이다. 사용자와 컴퓨터를 `my`, `cpu`로 구분하고 있어서 크게 신경 쓰지 않았다. 코딩 코치님은 `my_sel`이 `my_select`의 줄임말이라면 주석에 전체 단어를 적어 두는 게 좋겠다고 했다.

이 피드백 이후로는 변수 이름을 누구나 알아보기 쉽게 지었던 것 같다!

## 주석

주석은 변수 이름 다음으로 피드백에서 가장 많이 나왔다.

변수 이름이 줄임말이거나 자세한 설명이 필요하면 주석으로 적으라고 했다. 함수를 만들 때도 어떤 동작을 하는지, 함수의 정의나 실행 방법·조건 같은 내용을 적어 두면 가독성과 코드 이해도가 좋아진다고 했다. 라이브 코칭에서도 주석 팁이 잠깐 나왔는데, 팀 프로젝트나 회사에서는 혼자 쓰는 코드가 아니니 뜻이 있는 모든 부분에 주석을 다는 습관을 들이면 좋다고 했다.

파이썬에서는 `#`을 쓴 주석과, `"""..."""`(큰따옴표 3개)로 쓰는 독스트링을 쓸 수 있다. `'''...'''`(작은따옴표 3개)로도 주석 블록을 만들 수 있다.

독스트링은 함수 시작 부분에서 함수 인터페이스를 설명하는 문자열이다. doc은 documentation의 줄임말이다. 독스트링에는 함수를 쓰는 데 필요한 정보가 들어 있어야 한다.

- 함수가 어떻게 동작하는지 (엄청 자세하지 않아도 된다)
- 함수가 무엇을 하는지
- 각 인자가 함수의 어떤 동작에 영향을 주는지
- 타입이 분명하지 않다면, 각 인자에 어떤 타입을 넣어야 하는지

내가 만든 함수인데도 설명하기 어렵거나 잘 이해가 안 되는 순간이 온다면, 독스트링을 쓰면서 인터페이스를 다듬어 보는 게 도움이 될 것 같다.

> 참고
>
> - 인자(argument): 함수를 호출할 때 실제로 넘기는 값
> - 매개변수(parameter): 함수를 정의할 때 함수 안에서 쓰는 '변수'

예를 들어 미션 중에 '에라토스테네스의 체'를 쓰는 문제가 있었다. 전체 코드 중 일부만 가져왔다.

```python
def prime(n):
    sieve = [True] * n  # 에라토스테네스의 체 초기화: 자연수 n까지 모두 True(소수로 간주)
    m = int(n ** 0.5)
    for i in range(2, m + 1):  # 1은 제외하고 2부터
        if sieve[i] == True:  # i가 소수인 경우
            for j in range(i + i, n, i):  # i 다음부터 n까지 i의 배수인 j를 모두 False 처리
                sieve[j] = False
    return [i for i in range(2, n) if sieve[i] == True]
```

소수를 구하는 방법 중 하나인데 이해하기가 너무 어려워서, 한 줄 한 줄 무슨 뜻인지 주석으로 적었다. 어떤 동작과 흐름인지 알게 되니 오류를 고치기도 편했다.

```python
"""
학생 답안지와 정답지를 비교해 점수를 계산하고,
점수가 높은 순서대로 학생 이름과 점수를 출력하는 함수

점수 계산
정답지 a[i]와 s_score[i]에 저장된 답안을 for 문으로 비교
  - 두 값이 같으면 score에 +10점
  - 두 값이 다르면 점수 변경 없이 다음 인덱스로
이 for 문이 끝나면 다음 학생의 답안과 정답지를 비교
"""

for v in range(len(s)):
    s_person = s[v].split(',')
    s_score = [int(i) for i in s_person[1]]
    score = 0
    for i in range(10):
        x, y = (a[i], s_score[i])
        if x == y:
            score += 10
        else:
            score = score
    total.append([s_person[0], score])  # 채점 결과 리스트에 학생 이름과 점수 추가
```

이 문제를 풀 때 반복문에서 오류가 엄청 났는데, 그때마다 이 코드가 무슨 뜻인지 주석으로 적어 가며 디버깅했다. 제출한 코드에는 없지만, 연습할 때는 실패한 코드를 지우지 않고 주석 처리한 뒤 오류가 난 이유도 같이 적어 두었다. 모든 부분에 주석을 달아 두니 오류 원인을 찾기도 쉬웠고, 나중에 부족한 이론이 뭔지 찾아보기도 편했다.

## 들여쓰기

파이썬 IDE로는 보통 파이참, 비주얼 스튜디오 코드, 주피터, IDLE 등을 쓴다. 들여쓰기 한 번은 스페이스 4번 또는 탭 1번이다.

그런데 다른 프로그램이나 웹에서 코딩하다 보면 들여쓰기 크기가 다를 수 있다. 예를 들어 같은 Colaboratory를 썼는데, 설정이 달랐는지 내 들여쓰기는 4칸이고 팀원 A는 2칸이었다. 들여쓰기가 다르니 코드를 붙이거나 고칠 때 내용에 집중하기 어려웠다.

다른 사람과 협업할 때는 환경 설정을 맞추고, 문제가 될 만한 부분을 한 번 점검하고 시작하는 게 좋겠다고 생각했다. 우리 조는 조금 늦게 모여서 이런 사전 확인 없이 바로 미션부터 풀었고, 한참 지나서야 에디터 설정이 달랐다는 걸 알았다 ㅜ
